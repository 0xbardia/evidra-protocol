# Evidra Protocol — Product UI Requirements for Phase 2

These are product requirements, not a Phase 0 frontend design.

- Professional premium landing experience.
- Polished motion design with meaningful scroll/reveal transitions.
- Micro-interactions that clarify action, validation, pending state, and completion.
- Minimal, user-friendly product UI.
- Strong mobile design; mobile is not a shrunken desktop layout.
- Built-in documentation and guides.
- No generic AI color palette.
- No purple/cyan AI gradients as the default identity.
- Use vivid, distinctive, mature colors.
- Avoid AI-slop visual language.
- Avoid generic “unlock the power of AI” copy.
- Avoid decorative cards with no product purpose.
- Motion should explain protocol state, evidence, or transaction lifecycle where possible.
- Establish a protocol/infrastructure visual identity.
- Use appropriate mono typography for hashes, IDs, addresses, and data.
- Public Fact pages must feel verifiable and trustworthy.
- Accessibility is required: keyboard navigation, visible focus, semantic structure, sufficient contrast, labels, live status updates, and reduced-motion support.

Fact pages must make the canonical/latest/freshness distinction visible without requiring users to understand the contract internals. A polished surface must not hide unresolved, stale, callback-pending, or projection-lag states.
